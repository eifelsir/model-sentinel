# Model Sentinel · 模型哨兵

[English](README.md) · [下载 Windows 便携版](https://github.com/eifelsir/model-sentinel/releases/latest) · [反馈问题](https://github.com/eifelsir/model-sentinel/issues/new/choose)

Windows 大模型回答一致性检测工具。填写自己的 Base URL 和 KEY，定期用固定题目检测多个模型，通过桌面悬浮窗查看答案、状态、生成页面和 Token 用量。

## 功能

- 支持 Responses API、Chat Completions、Gemini 原生和 Claude Messages；可接入 OpenAI、Grok、Gemini、Claude 及兼容中转。
- 支持拉取模型列表、手动添加、多 URL、多模型、多题并发检测和定时检测。
- 内置牛奶题、糖果题和 HTML/SVG 动画题，可修改或新增题目。
- 文字题在本地提取最终答案并核对；HTML 题生成完整 SVG 页面，不需要固定答案。
- 文字题完成即更新状态和色条，HTML 继续生成供人工查看，不影响文字判定；队列优先执行文字题。
- 可选择当前模型或其他已配置模型辅助提取难以识别的答案，保留原文依据，单独记录辅助 Token。
- 收起和展开悬浮窗均按“连接名称 · 模型名称”显示，长名称分别省略、悬停看全名；收起时可看历史色条、文字答案和本轮 Token，展开后查看最近 60 轮记录。
- HTML 题在展开悬浮窗显示最近 8 轮真实缩略图，点击后向下展开交互页面，同轮多题可切换。
- 按模型和协议选择支持的推理强度，单独设置输出 Token 上限、超时和额外请求参数。
- 工作台和设置页可开启“绕过缓存”，覆盖文字、HTML 和辅助提取请求，自动保存开关状态并在详情记录。
- 每题、每轮显示输入、输出、总计及服务提供的缓存和推理 Token；设置页查看保留历史与逐模型汇总。
- 配置和历史保存在本机，KEY 经 Windows 加密，原子保存并写入备份，导出不包含已保存的 KEY。

## 开始使用

1. 从 [Releases](https://github.com/eifelsir/model-sentinel/releases/latest) 下载并打开 `Model-Sentinel-1.2.1-Windows-x64.exe`，无需安装 Node.js。
2. 在检测工作台选择内置题目，或填写提示词和固定答案后保存。页面生成请选择“HTML / SVG 动画”。
3. 在“连接与模型”填写 Base URL、KEY 和协议，拉取列表或手动添加模型。
4. 为每个模型选择关联题目并检测；需要定时运行时开启自动检测。

默认每 30 分钟检测一轮、最多 4 个请求并发、单次超时 180 秒，均可修改。开启自动检测会立即运行；停止全部检测同时暂停自动检测。

关闭主窗口后程序保留在托盘，托盘“退出”才会关闭程序。点击悬浮窗展开，拖动标题栏移动。升级前先从托盘退出旧版，再运行新版，沿用已有配置。设置页显示程序版本和实际保存路径。

## 判定和用量

| 状态 | 含义 |
| --- | --- |
| 正常 | 全部文字题答案匹配，不等待 HTML，HTML 成败不影响该状态 |
| 降智 | 至少一道题提取到明确答案，但与固定答案不一致 |
| 结果不足 | 没有明确答错，但文字题存在失败、超时、截断、拒答或无法明确提取的答案 |
| 已生成 | 纯 HTML 题成功生成完整 SVG 页面，不表示页面质量通过评分 |

固定答案仅在本地比对，默认关闭绕过缓存，原始检测提示词原样发送。自动提取支持带单位的结论、LaTeX 框选答案，明确冲突或不确定的结论保留结果不足，也可选择全文比对或正则提取。多道文字题全部完成后显示正常，有明确答错则立即显示降智；HTML 保留生成状态和预览供人判断。

设置中的“答案辅助判定模型”默认关闭。可以选“当前被测模型”或其他已配置模型，仅在本地自动提取不明确时补充调用一次。辅助模型读取已隐藏配置 KEY 的题目和回复，不接收固定答案，必须返回原文中存在的完整答案与引用；工具随后在本地核对。详情展示辅助模型、原文依据和用量，辅助失败时保留结果不足。已识别的冲突、不确定结论、未完成算式，以及请求失败、拒答、截断和 HTML 题不触发辅助调用。中途取消的辅助请求仍计为一次用量未知的记录。辅助模型也可能误判，有争议时请核对引用。

“降智”仅代表当前测试答错，无法证明模型的整体能力、身份或服务商是否换了模型。接口请求和启用后的辅助调用可能产生服务商费用，工具不会隐式重试。

Token 以接口返回为准，不按文字长度估算；缺失项显示“未提供”，部分记录缺少用量时标明“部分”。缓存和推理是对应输入、输出的细项，不重复加到总计。汇总范围是本机保留的最多 1,000 轮已完成记录及当前检测，不是账户终身账单；旧记录不会补造用量。

本轮总用量包含实际发生的辅助调用；按模型汇总时归属到实际辅助模型，不重复记到被测模型。辅助用量缺失时同样标明未提供或部分。

### 缓存会影响检测吗

工具每次检测都会发起新请求，不在本地缓存答案，也不把上一轮回复拼入聊天历史。服务商的提示词或前缀缓存复用的是输入计算，仍会生成新回答。例如 [OpenAI 提示词缓存](https://developers.openai.com/api/docs/guides/prompt-caching)不改变输出，命中本身不会让答案检测失效，但会影响耗时和费用，不能视为首次处理输入时的延迟。

中转的整条回复缓存则可能直接返回旧答案，不再调用当前模型，例如 [LiteLLM 的回复缓存](https://docs.litellm.ai/docs/proxy/caching)。持续监测当前服务表现时，应关闭这类缓存。后台只写“命中缓存”无法确定是哪一种；输入侧的缓存读取 Token 也不代表整条答案被重放。

工作台和设置中的“绕过缓存”默认关闭。开启后，从下一轮起为每次文字、HTML、辅助提取请求添加新的随机前缀，前缀后保留原题，发送不复用缓存的请求头，并忽略额外 JSON 中显式复用缓存的字段。检测详情保留“已请求绕过缓存”标记，关闭后恢复原始题目和配置的缓存选项；拉取模型列表不受影响。

随机前缀用于减少相同请求和相同输入前缀的复用，不能保证中转遵守请求头，也无法保证绕过按题意匹配的语义缓存；后台仍可能报告部分缓存命中。前缀会改变模型看到的输入并增加少量 Token，可能影响回答和费用。若要确认服务端完全不复用旧回复，仍需使用服务商的缓存设置。

## 本地数据

正常保存位置为 `%APPDATA%/Model Sentinel`。KEY 由 Windows 当前用户加密，迁移到其他电脑或账户后可能需要重新填写。配置写入加密备份，主文件缺失时可恢复；检测历史和导出文件包含题目、回复及生成页面，分享前请检查内容。

页面预览在独立沙箱中运行，限制访问应用接口、Node、外部网络、弹窗、表单和外部跳转。页面应使用内嵌素材。休眠和程序退出期间不会执行定时检测。
